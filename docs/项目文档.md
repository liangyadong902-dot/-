## 1. Objective

做一套可上线的「途个惊喜」平台，而不是只还原单文件原型。

**用户**：想说走就走的年轻旅行者。按心情选盲盒，支付后随机解锁价值保底线路。

**运营 / 客服 / 财务**：在管理端配置盲盒与线路，处理订单退款，看用户与成交数据。

**核心闭环**

```text
选心情 → 筛盲盒 → 登录 → 支付 → 开盒抽线路
  → 写入行程 / 徽章 → 查看详情 / 日记 / AI 搭子
```

### 1.1 用户故事（平台范围）

| ID | 作为… | 我想… | 以便… |
|---|---|---|---|

| US-02 | 登录用户 | 支付后开一个盲盒 | 随机解锁票面价值保底的线路 |

### 1.2 商业模式（怎么赚钱）

钱是用户**买盲盒**付出来的，不是 AI、徽章或统计直接收费。支付宝沙箱只用于打通支付，答辩演示不产生真实收入。

```text
用户付售价（如 ¥99）
        │
        ├─ 线路采购结算（真正的成本，低于票面价值）
        ├─ 支付宝手续费（正式环境约 0.6%，沙箱为 0）
        ├─ 乡村文旅扶持 1 元/单（承诺支出，不是利润）
        └─ 剩下 = 平台毛利
```

**「票面价值保底 120%」不是亏本卖。** 票面是线路门市价/包装价值，采购价通常明显更低。用户感知「省了 21 元」，平台赚的是售价减结算价。

| 收入 | 说明 | 本期 |
|---|---|---|
| 盲盒销售收入 | 唯一主营。7 档售价 89–999，客单价看品类结构 | **做** |
| 复购开盒 | 徽章、人格、心情推荐把人留下，第二次开盒边际成本更低 | **做**（产品能力） |
| 商家/线路方抽成 | 以后供应商入驻，按单抽佣 | 不做，文档里仍是自营池 |
| AI 会员、广告 | 小途是转化工具，不设咨询费 | 不做 |

| 成本 / 损耗 | 说明 |
|---|---|
| 线路结算 | 最大头；管理端要能配结算价（可在线路表扩展 `cost_cent`） |
| 支付手续费 | 正式支付宝；沙箱无 |
| 公益 1 元 | 每有效单固定支出 |
| 退款 | 抽奖失败、未出行退换；退了就没有该单毛利 |
| 大模型调用 | 小途/日记的 token，用免费额度或低价模型控制 |

**一单示意（周边微度假 ¥99，保底票面 ¥120）**

| 项 | 金额 |
|---|---|
| 实收 | 99 |
| 假设结算给线路方 | 65 |
| 公益 | 1 |
| 手续费约 | 0.6 |
| 毛利约 | **32.4** |
| 用户看到的「累计省钱」 | 120 − 99 = **21**（营销数字，不是平台亏损） |

跨省 ¥999 毛利更高，但也更依赖能谈下来的结算价和退款率。经营上看三件事：客单价、复购率、退款率。

管理端「成交额」是 GMV；真正赚不赚钱要看以后加上结算价之后的毛利报表。第一期可以先只记 GMV 和退款，线路表预留 `cost_cent`。

## 2. 系统架构

```text
┌─────────────┐     ┌─────────────┐
│  用户端 H5   │     │  管理端 Web  │
│  Vue3 移动宽 │     │  Vue3 PC    │
└──────┬──────┘     └──────┬──────┘
       │ HTTPS / SSE       │
       └────────┬──────────┘
                ▼
        ┌──────────────────────────┐
        │  Spring Boot 服务         │
        │  鉴权 · 订单 · 开盒       │
        │  Spring AI 小途智能体     │
        └───────────┬──────────────┘
              ┌─────┼──────┬─────────┐
              ▼     ▼      ▼         ▼
           MySQL  Redis   大模型   支付宝沙箱
          业务+长期  验证码  OpenAI   跳转收银台
          记忆      会话窗  兼容接口  异步 notify
                    支付锁
```

- 用户端、管理端共用一套后端，路径前缀分开（`/api/v1` 与 `/api/v1/admin`）。
- 开盒抽奖、订单状态、统计口径全部在服务端计算，前端不自己改出行次数或徽章。
- 小途对话走 Spring AI（记忆 + 工具 + 可选 RAG）；模型失败时关键词降级。详见 `docs/AI智能体设计.md`。
- 原型里的 `localStorage` 只作为**尚未接 API 时的过渡**，接上后端后行程/徽章/订单以服务端为准。

### 6.3 开盒（含支付）

1. 点「开盒」→ 未登录先登录，再回到确认弹窗。  
2. 展示名称、售价、保底；点「立即开启惊喜」→ **创建待支付订单**。  
3. 收银台只展示支付宝；点「去支付宝付款」→ **整页跳转沙箱收银台**（电脑演示用 page.pay，手机用 wap.pay）。15 分钟未付自动取消。  
4. 用户付完后支付宝跳回结果页；前端**轮询订单**直到已开盒。服务端以**异步 notify 验签**为准再抽线路。  
5. 已开盒后播礼盒 `shake` 1.2s 并翻牌；写入行程、解锁徽章、更新统计。「查看行程」切 Tab。  
6. 抽奖失败（池不满足保底）→ 支付宝沙箱退款，不产生有效行程。

### 6.4 等级与「我的」统计（按功能设计，不再写死）

| 出行次数（有效行程） | 称号 |
|---|---|
| 0–2 | 旅行新手 |
| 3–7 | 探索者 |
| ≥8 | 旅行家 |

- 累计省钱 = Σ（票面价值 − 购入价），仅有效行程。  
- 当前等级 Lv.N，N = max(1, 出行次数)。  
- 公益里程 = 有效支付订单数（1 单 = 1 里程 = 1 元扶持金）。  
- 已解锁线路数 = 有效行程数（纠正原型用徽章数的算法）。

### 6.5 AI / 图鉴 / 行程

图鉴 12 徽章、5 题人格测试与原型一致。空行程文案不变。人格测试未登录可做，登录后才持久化。

## 7. Code Style

- 前端：组件 `PascalCase.vue`；composable `useXxx.ts`；业务状态进 Pinia。  
- 后端：包按 `controller / service / mapper / domain`；表名、字段见数据库文档。  
- 禁止前端直接改「已支付 / 已开盒」；只展示接口结果。  
- 抽线路必须 `value >= box.minValue`，随机可注入 RNG 便于单测。

```ts
export function pickRoute(box: BlindBox, pool: Route[], rng = Math.random): Route {
  const valid = pool.filter((r) => r.value >= box.minValue && r.enabled)
  if (!valid.length) {
    throw new Error(`No route satisfies minValue=${box.minValue}`)
  }
  return valid[Math.floor(rng() * valid.length)]
}
```

## 9. Boundaries

**Always**

- 未支付成功不得抽线路。  
- 统计只计「已开盒且未退款」的有效数据。  
- 对照原型核对文案和价格。  
- 密钥、真实用户数据不进仓库。

**Ask first**

- 改技术栈、切正式支付宝商户、接微信支付、换模型供应商、做小程序。  
- 改品牌色或信息架构。  
- 增加供应商子账号或独立工单模块。

**Never**

- 开盒结果写死为固定线路冒充随机。  
- 删除或改坏 `prototype/index.html`。  
- 为通过测试删除失败用例。

## 10.1 比赛交付：要可演示，不必正式上线

评委看的是 **能不能当场把闭环跑通、技术点是否扎实**，不是有没有 App Store / 备案网站。

**要有**

- 本机或一台云主机上的完整环境：H5 + 管理端 + Spring Boot + MySQL + Redis  
- 支付宝**沙箱**跳转支付（假钱，证明你接过真实支付链路）  
- 小途能对话（模型可用就现场调；怕断网就准备降级话术 + 录屏）  
- 3～5 分钟演示脚本：选心情 → 登录 → 沙箱付款 → 开盒 → 行程/徽章 → 管理端能看到订单  
- **备用录屏**（现场网不行、沙箱挂了也能讲）  
- 文档与架构图（你们已经在写）

**不必有**

- ICP 备案、正式域名长期挂着  
- 支付宝正式商家签约、真实扣款  
- 微信小程序提审  
- 真实短信通道（验证码可控制台打印或固定码）  
- 7×24 运维、CDN、压测到万级 QPS  

如果比赛要求「提供访问地址」，用临时 HTTPS（云主机 + 穿透/测试域名）挂几天即可，这是 **演示部署**，不是产品上线。
