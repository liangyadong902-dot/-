## 1. 技术栈变更声明

`docs/项目文档.md` 原定「用户端 Vue 3.5 + Vite H5」，**本期变更如下**：

| 端 | 原方案 | **本期方案** |
|---|---|---|
| 用户端 | Vue 3.5 + Vite + TS + Tailwind（移动 H5） | **原生微信小程序**（WXML + WXSS + JS/TS） |
| 管理端 | Vue 3.5 + Vite + TS + Element Plus | **不变** |
| 后端 | Spring Boot 3 + MyBatis-Plus + JDK 17 | **不变** |
| 数据库 / 缓存 | MySQL 8 / Redis | **不变** |
| AI | Spring AI（单智能体小途 + Memory + Tool） | **不变** |
| 支付 | 支付宝沙箱跳转收银台 | **支付宝沙箱 + 二维码/外部浏览器** |

### 1.1 原型一比一还原硬性规范

小程序和管理端必须以现有 HTML 原型为唯一视觉与交互基准，**一比一还原，不允许自行改版**：

| 端 | 唯一原型基准 | 还原范围 |
|---|---|---|
| 用户端小程序 | [`docs/页面原型.html`](页面原型.html) | 页面结构、布局、尺寸、颜色、字体层级、间距、圆角、阴影、图标、文案、动效、弹窗、底部导航和交互流程 |
| 管理端 Web | [`docs/管理端页面原型.html`](管理端页面原型.html) + [`docs/管理端页面原型.js`](管理端页面原型.js) | 侧栏分组、顶栏、页面布局、表格、卡片、筛选器、抽屉、弹窗、按钮、状态、文案和交互行为 |

执行规则：

1. HTML/CSS/JavaScript 只允许转换为 WXML/WXSS/小程序 API 或 Vue/Element Plus 实现，**不允许改变最终呈现结果**。
2. 不得擅自改变布局、颜色、字体、字号、间距、圆角、阴影、图标、文案、页面顺序、导航结构或交互流程。
3. 新增社区、打卡、成就、商家、积分功能必须沿用原型既有视觉 Token、组件风格和交互语言；未经确认不得另起设计风格。
4. 原型中的每个页面、弹窗、空态、加载态、错误态、列表态、详情态和操作反馈都属于还原范围，不能只还原静态首页。
5. 每个阶段验收必须逐页对照原型，覆盖桌面/移动尺寸、关键状态和主要交互；提交截图或录屏作为验收证据。
6. 原型与接口字段冲突时，保持原型的视觉和交互不变，通过适配层转换数据；不得为了方便后端字段而修改页面。
7. 一比一还原未完成时，不能以“功能可用”作为该页面验收通过的依据。

### 1.2 原型还原验收记录

每个页面必须建立以下记录后才能标记完成：

| 项目 | 要求 |
|---|---|
| 页面清单 | 与 HTML 原型逐页对应，不能漏页 |
| 静态对照 | 初始态截图与原型截图尺寸一致 |
| 状态对照 | 加载、空数据、错误、已登录、未登录、弹窗、抽屉等状态逐项核对 |
| 交互对照 | 点击、筛选、切换、返回、关闭、提交、提示、动效与原型行为一致 |
| 响应式/设备 | 小程序至少核对开发者工具与真机；管理端核对原型目标桌面尺寸 |
| 偏差处理 | 任何偏差登记文件、原因和修复结果；未确认的偏差不得关闭 |

## 9. 关键技术决策

### 9.1 小程序支付方案（方案B）

| 项目 | 结论 |
|---|---|
| 主路径 | 二维码/复制链接到外部浏览器 |
| 后端返回 | `pay_url`（沙箱收银台）+ `qr_code_base64`（二维码） |
| 演示方式 | 小程序展示二维码，演示者扫码在浏览器完成支付 |
| 备份 | `pay.mock_enabled=true` 模拟支付 |

### 9.2 AI流式方案（方案C）

| 项目 | 结论 |
|---|---|
| 主路径 | 整段返回 + 前端打字机 |
| 实现 | `POST /ai/chat` 返回完整文本，前端逐字渲染 |
| 备份 | 关键词降级（`ai_keyword_rule`） |

### 9.3 登录方案

| 项目 | 结论 |
|---|---|
| 手机号 | 自建短信验证码（本期固定码） |
| 微信 | `wx.login` → 后端 `code2session` → JWT |
| Token | JWT，7天有效期，自动续期 |
