# 阶段二：内容域详细开发计划

> 版本：v1.0  
> 阶段：Phase 2  
> Timebox：2 周（10 个工作日）  
> 用户端形态：原生微信小程序  
> 依据：`docs/功能模块设计.md`、`docs/开发计划.md`、`docs/项目文档.md`、`docs/接口设计.md`、`docs/数据库设计.md`、`docs/openapi.yaml`

> **原型还原硬性要求：** 微信小程序用户端必须与 `docs/页面原型.html` 的最终呈现和交互**一模一样**。页面结构、布局尺寸、颜色、字体、字号、字重、间距、圆角、阴影、图标、图片比例、文案、页面顺序、底部导航、弹窗、动效、加载态、空态、错误态和点击行为均不得产生产品层面的差异。小程序只是技术载体转换，不能借机改版、简化或重新设计。

## 1. 阶段目标与边界

本阶段完成“管理端配置 → 后端接口 → 微信小程序展示”的内容链路，交付盲盒、线路、徽章、Banner 的配置能力，以及小程序首页和图鉴页。

### 1.1 本阶段交付

- 盲盒、线路、徽章、Banner 的管理端 CRUD、上下架、分页、筛选和权限控制。
- 小程序首页：品牌栏、心情筛选、分类筛选、Banner、盲盒列表、加载/错误/空状态和盲盒预览弹窗。
- 小程序图鉴页：12 枚徽章、解锁状态、解锁时间和收集进度。
- 心情选择日志接口，为后续统计提供数据。
- 内容接口、DTO 字段映射、金额转换、异常处理、线路池保底校验和阶段验收记录。

### 1.2 明确不做

- 不实现真实登录、下单、支付宝支付、开盒抽线路、行程写入、退款、人格测试和 AI。
- 开盒弹窗只展示盲盒信息并预留事件，不创建订单、不扣库存、不产生开盒结果。
- 不实现图片上传，内容图片只保存和展示 URL。
- 社区、打卡、成就、商家和积分属于后续阶段。

## 2. 前置条件与技术约定

- 阶段一验收通过：`server/`、`admin-web/`、`miniapp/` 可启动，数据库和种子数据已导入，JWT 与统一响应体可用。
- 用户端按最新总计划使用原生微信小程序（WXML + WXSS + JS/TS）。
- `docs/页面原型.html` 是用户端唯一视觉和交互基准；不得以《功能模块设计.md》中的概括描述替代原型细节。
- 原型中的 CSS 值、DOM 层级、组件顺序、固定文案和状态行为须逐项登记并转换；无法直接转换的浏览器能力必须通过小程序等价实现达到相同结果。
- `docs/openapi.yaml` 是接口字段和响应结构的唯一来源；发现冲突时先统一文档，再编码。
- 继续使用现有 `blind_box`、`blind_box_mood`、`blind_box_scene`、`travel_route`、`badge`、`user_badge`、`banner`、`mood_log` 表，不新增业务表。
- 数据库金额使用分，接口金额使用元；转换集中在 DTO/Assembler 层，业务代码不散落 `/100`。
- 管理端 `super_admin`、`operator` 可编辑内容；`analyst` 只读；`cs`、`finance` 无内容写权限。权限必须由服务端强制校验。
- 小程序沿用阶段一 TabBar 和占位页，本阶段只完成首页与图鉴页。
- 所有列表查询显式排序；管理端分页统一返回 `list、total、page、pageSize`。

## 3. 接口契约与后端内容服务

### 3.1 用户端接口

| 方法 | 路径 | 关键行为 |
|---|---|---|
| GET | `/api/v1/banners` | 只返回 `status=on` 且处于 `start_at/end_at` 生效窗口的 Banner，按 `sortWeight DESC` 排序 |
| GET | `/api/v1/boxes?category=&mood=` | 只返回上架盲盒；分类和心情采用 AND 过滤；缺省或 `all` 表示不筛选 |
| GET | `/api/v1/boxes/:id` | 返回盲盒详情、适配心情和适配场景 |
| GET | `/api/v1/badges` | 未登录时 `unlocked=false`；登录后按 `user_badge` 标记，返回 `{ total, list }` |
| POST | `/api/v1/mood-logs` | 游客也可提交，记录 `mood` 和可选 `boxId` |

实现要求：

- 盲盒用户端只查 `status=on`，按 `sort_weight DESC, id ASC` 排序。
- 心情过滤通过 `blind_box_mood` 关联表完成；分类和心情同时传入时必须同时满足。
- Banner 需处理空的起止时间：`start_at` 为空视为立即生效，`end_at` 为空视为长期有效。
- 盲盒详情不存在或已下架时返回 `404`，不向游客暴露下架内容。
- 徽章总数来自实际定义数量，不能把 12 写死为接口结果；前端默认展示种子数据的 12 枚。
- 心情日志只记录合法枚举值；重复日志不得改变盲盒筛选结果。

### 3.2 管理端接口

| 资源 | 接口 | 说明 |
|---|---|---|
| 盲盒 | `GET/POST /api/v1/admin/boxes` | 分页查询、创建；支持分类、状态、关键字筛选 |
| 盲盒 | `PUT/DELETE /api/v1/admin/boxes/:id` | 更新或删除；存在未完成订单时禁止删除 |
| 盲盒 | `PATCH /api/v1/admin/boxes/:id/status` | 上架/下架 |
| 盲盒 | `GET /api/v1/admin/boxes/:id/pool` | 返回线路池、满足保底线路和 `ok` 标志 |
| 线路 | `GET/POST /api/v1/admin/routes` | 分页查询、创建；支持分类、状态、徽章筛选 |
| 线路 | `PUT/DELETE /api/v1/admin/routes/:id` | 更新或删除；有历史引用时禁止物理删除并提示下架 |
| 线路 | `PATCH /api/v1/admin/routes/:id/status` | 上架/下架 |
| 徽章 | `GET/POST /api/v1/admin/badges` | 分页查询、创建，并聚合解锁人数和关联线路数 |
| 徽章 | `PUT /api/v1/admin/badges/:id` | 更新；已有徽章定义不提供删除 |
| Banner | `GET/POST /api/v1/admin/banners` | 分页查询、创建 |
| Banner | `PUT/DELETE /api/v1/admin/banners/:id` | 更新或删除 |
| Banner | `PATCH /api/v1/admin/banners/:id/status` | 上架/下架 |

### 3.3 后端分层与校验

按 `controller/service/mapper/domain` 分层新增内容域代码，统一复用阶段一的 `Result<T>`、`PageResult<T>` 和全局异常处理。

- 新增内容实体映射、查询条件、请求 DTO、响应 DTO 和金额/JSON 转换器。
- 盲盒保存时检查同分类上架线路中是否存在 `value_cent >= min_value_cent` 的线路；无满足线路时允许保存，但响应返回 `warning`。
- 线路池查询必须返回全部候选线路、满足保底的线路和 `ok`；不修改任何交易数据。
- 删除盲盒前检查 `biz_order.status IN ('pending_pay','paid')`；命中返回 `409`。
- 删除线路前检查订单/行程引用；有历史引用时拒绝物理删除，提示改为下架。
- Banner 的 `jumpType` 只允许 `none/category/box/url`；无效跳转目标保存时返回参数错误，不得导致用户端查询 500。
- 价格、保底、票面价值、采购价必须为非负数；保底和票面价值支持两位小数输入。
- 名称、分类、状态、徽章关联、Banner 时间范围和 JSON 数组字段均在服务端二次校验。
- 资源不存在返回 `404`，参数错误返回 `400`，无权限返回 `403`，业务冲突返回 `409`。

## 4. 管理端实现计划

管理端复用阶段一布局、Axios 实例、`useTable`、分页组件、权限指令和统一错误提示，不使用本地假数据作为成功结果。

### 4.1 盲盒管理 `views/boxes/List.vue`

- 筛选：关键字、分类、上下架状态。
- 表单字段：名称、分类、展示标签、角标、简介、售价、保底、封面 URL、适配心情、排序、状态。
- 列表字段：名称、分类、售价、保底、适配心情、状态、开盒次数、更新时间。
- 操作：新建、编辑、上下架、删除、批量上下架/删除、线路池抽屉。
- 线路池抽屉展示线路名、目的地、分类、票面价值、徽章、抽中次数、状态和是否满足当前保底。
- 保存后展示保底校验告警；告警不阻断保存，但必须可见。

### 4.2 线路管理 `views/routes/List.vue`

- 筛选：关键字、分类、状态、徽章。
- 表单字段：名称、分类、目的地、场景、票面价值、采购价、徽章、亮点、包含服务、情绪文案、状态。
- 列表字段：线路名、目的地、分类、票面、徽章、抽中次数、状态。
- 校验：名称和目的地必填，票面价值非负，分类为合法枚举，徽章必须存在。
- 有历史订单/行程的线路删除操作显示不可删除原因，并提供下架入口。

### 4.3 徽章管理 `views/badges/List.vue`

- 列表展示印章字、名称、描述、排序、解锁人数、关联线路数。
- 支持新建和编辑；已有徽章定义不显示删除操作。
- `mark` 最多 4 个字符，名称唯一，排序值使用整数。

### 4.4 Banner 管理 `views/banners/List.vue`

- 列表展示标题、副标题、标签、图片、跳转类型、有效期、排序和状态。
- 表单支持预览、创建、编辑、上下架和删除。
- `jumpType=category` 时选择合法分类；`box` 时选择盲盒；`url` 时填写合法 URL；`none` 不显示目标字段。
- 校验 `startAt <= endAt`；空时间表示立即生效或长期有效。

## 5. 微信小程序实现计划

### 5.1 首页

新增或完善以下目录：

```text
miniapp/
├── pages/index/index.{js,wxml,wxss,json}
├── components/BrandHeader/
├── components/MoodSelector/
├── components/BannerSwiper/
├── components/CategoryTabs/
├── components/BlindBoxCard/
├── components/OpenBoxModal/
└── components/EmptyState/
```

实现要求：

- 先按 `docs/页面原型.html` 建立页面基线：逐段对应原型 DOM，逐项迁移 CSS Token、布局尺寸、字号、颜色、边框、阴影、圆角、图片裁切和动效参数；禁止使用“相近样式”代替原值。
- 原型中的固定区域、模块顺序、标题层级、按钮文案、空状态文案和底部导航必须保持原样；接口只替换数据来源，不改变呈现结构。
- 首次进入并行请求 Banner 和盲盒列表，展示加载态、失败重试和下拉刷新。
- 点击心情先提交 `POST /mood-logs`，再按当前分类与心情刷新盲盒列表；日志失败不阻断浏览，但需保留筛选动作。
- 分类和心情筛选同时生效；无结果显示原型规定的空状态文案。
- Banner 跳转：`category` 回首页并选中分类，`box` 打开盲盒预览，`url` 调用小程序合法外链能力，`none` 无操作。
- 盲盒卡片展示名称、标签、简介、售价、保底和封面；价格从接口实时读取。
- 盲盒预览弹窗展示名称、售价、保底、简介和适配心情；“立即开启惊喜”仅触发预留事件，不调用订单接口。
- 页面数据以服务端为准，不使用本地缓存覆盖价格、上下架状态或列表内容。

### 5.2 图鉴页

新增或完善以下目录：

```text
miniapp/
├── pages/badges/index.{js,wxml,wxss,json}
├── components/BadgeSeal/
└── components/ProgressBar/
```

- 请求 `/api/v1/badges`，展示 `unlocked / total` 和进度百分比。
- 徽章三列网格展示，未解锁状态灰度并显示锁定样式，已解锁状态展示解锁时间。
- 未登录调用接口后全部显示为未解锁；不在前端猜测用户徽章。
- 总数取接口 `total`，种子数据应展示 12 枚。
- 图鉴页的入口卡片、徽章网格、测试入口占位、标题层级、进度条和底部导航必须逐像素对齐原型；本阶段未实现的业务只保留原型中的视觉和交互占位，不得删除或改成其他布局。

## 7. 测试计划与验收标准

### 7.0 原型一致性验收（硬性门槛）

- 以 `docs/页面原型.html` 为基准，在相同视口尺寸下对小程序首页、图鉴页及所有阶段二相关弹窗进行截图比对。
- 至少覆盖初始态、加载态、加载失败态、空结果态、心情筛选态、分类筛选态、Banner 跳转态、盲盒预览弹窗、游客图鉴态和演示用户解锁态。
- 对比项目包括：DOM/组件顺序、容器宽高、位置、颜色、字体、字号、字重、行高、间距、圆角、阴影、边框、图片裁切、图标、文案和动效时长。
- 截图必须使用固定视口和固定种子数据；每个页面保留“原型图、实现图、差异说明、修复后图”四项记录。
- 任何可见差异都必须修复或登记为阻塞问题；存在未确认差异时，不得标记阶段二验收通过。
- 视觉验收不能以“功能可用”“整体相似”或“微信平台限制”为通过理由；平台限制必须通过等价实现消除最终呈现差异。

### 7.1 后端测试

- 分类、心情、分类+心情组合过滤正确。
- 下架盲盒和过期 Banner 不出现在用户端。
- Banner 按状态、时间窗口和排序返回。
- 金额分转元无精度错误，空采购价正确返回 `null`。
- 盲盒线路池 `ok` 判断、满足线路筛选和保底告警正确。
- 存在未完成订单时删除盲盒返回 `409`。
- 有历史引用的线路无法物理删除。
- 无权限管理员写接口返回 `403`。
- 游客徽章全部锁定，登录用户按 `user_badge` 正确标记。
- 非法枚举、非法跳转类型、错误时间范围和负金额返回 `400`。
- 重复提交心情日志不会影响内容查询。

### 7.2 联调与手工验收

- 管理端将盲盒售价从 99 修改为 89，小程序下拉刷新后显示 89。
- 管理端下架某盲盒，小程序首页刷新后不再展示。
- 选择 `emo` 后只显示带 `emo` 标签的盲盒；切换分类后筛选条件仍正确叠加。
- 两条 Banner 正常展示，分类、盲盒和无跳转行为符合配置。
- 新用户图鉴显示 `0/12`，演示用户显示实际解锁数量。
- 盲盒预览弹窗不会创建订单、改变库存或伪造开盒结果。
- 375px 小程序页面与 `docs/页面原型.html` 逐页逐状态一比一对照，覆盖加载、空数据、错误、筛选和弹窗状态，差异项清零后才算通过。
- 管理端页面与 `docs/管理端页面原型.html`、`docs/管理端页面原型.js` 对照并保存截图。

## 9. 阶段完成定义

以下条件全部满足后，阶段二才算完成：

- 管理端内容修改真实写入数据库，并能通过接口查询。
- 小程序首页和图鉴页只使用后端数据，刷新后状态保持一致。
- 内容接口通过参数、权限、金额、时间窗口和资源状态测试。
- 原型要求的首页、图鉴、空状态、加载态、错误态和盲盒预览状态完成对照。
- 阶段二验收记录、截图和已知问题清单已归档，未完成项明确转入阶段三或后续阶段。
- 用户端原型对照记录中不存在未关闭的可见差异；否则阶段二不完成。
