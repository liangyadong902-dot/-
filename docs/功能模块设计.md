# 途个惊喜 — 功能模块设计

> 基于原型 `prototype/index.html` 推导  
> 文档类型：功能模块设计（不含技术实现）  
> 后续文档：`docs/项目文档.md` · `docs/数据库设计.md` · `docs/接口设计.md` · `docs/AI智能体设计.md`  
> 产品定位：盲盒式惊喜旅行平台，口号「随盒出发，途个好心情」

---

## 1. 产品总览

### 1.1 业务闭环

```text
用户选心情 → 浏览/筛选盲盒 → 支付开盒 → 随机解锁线路
    → 生成行程 → 解锁徽章 → 查看详情/生成日记 → AI 搭子咨询
```

### 1.2 端划分

| 端 | 使用角色 | 核心目标 |
|---|---|---|
| **用户端** | 普通旅行者 | 发现、支付开盒、出行、收集、咨询 |
| **管理端** | 运营 / 产品 / 客服 / 财务 / 管理员 | 配置内容、处理支付与用户、监控统计 |

### 1.3 模块关系图

```text
                    ┌─────────────────────────────────┐
                    │           管理端                 │
                    │  盲盒 │ 线路 │ 徽章 │ 运营 │ AI  │
                    │  订单 │ 支付 │ 用户 │ 统计 │ 系统 │
                    └──────────────┬──────────────────┘
                                   │ 配置下发 / 数据回传
                    ┌──────────────▼──────────────────┐
                    │           用户端                 │
                    │  首页 │ 开盒/支付 │ 行程 │ 图鉴  │
                    │  我的（账号/数据）│   AI搭子     │
                    └─────────────────────────────────┘
```

### 2.3 开盒模块

开盒为全局弹层，贯穿首页触发，结果写入行程与图鉴。

#### 2.3.1 开盒前确认

| 功能点 | 说明 |
|---|---|
| 盲盒信息 | 名称、售价、价值保底 |
| 礼盒动效区 | 礼盒图标展示 |
| 确认开盒 | 「立即开启惊喜」→ 进入支付（见 2.8） |
| 服务协议 | 「开启即代表同意服务规则」提示 |
| 关闭弹窗 | 右上角关闭；未支付不产生订单 |

**规则**：未支付成功不得抽线路；支付成功后自动进入开盒过程，不可退回「未开盒占坑」。

#### 2.3.2 开盒过程

| 功能点 | 说明 |
|---|---|
| 触发时机 | 支付成功回调后自动开始，用户无需再点一次 |
| 摇晃动效 | 礼盒摇晃约 1.2 秒 |
| 随机抽取 | 从该盲盒分类线路池中抽取，且 `票面价值 ≥ 保底价值` |
| 抽奖失败 | 池中无线路满足保底 → 开盒失败，自动全额退款并提示 |
| 结果翻牌 | 翻牌动画展示解锁线路 |

#### 2.3.3 开盒结果

| 功能点 | 说明 |
|---|---|
| 结果卡片 | 分类标签、线路名称、目的地、包含服务、票面价值 |
| 情绪文案 | 每条线路独立 `moodText`（如「古村的风会吹走所有烦恼」） |
| 收下惊喜 | 关闭弹窗，保留行程记录 |
| 查看行程 | 关闭弹窗并跳转行程 Tab |
| 副作用 | 订单变为「已开盒」；写入行程；解锁关联徽章；累计出行/省钱/公益里程 |

### 2.4 AI 搭子模块

#### 2.4.1 对话界面

| 功能点 | 说明 |
|---|---|
| AI 身份 | 「小途 · AI旅行搭子」，在线状态 |
| 开场白 | 固定欢迎语 |
| 消息列表 | 用户右对齐主色气泡；AI 左对齐白底气泡 |
| 自动滚动 | 新消息滚至底部 |

#### 2.4.2 输入与快捷问句

| 功能点 | 说明 |
|---|---|
| 文本输入 | 输入框 + 发送按钮，支持回车发送 |
| 快捷问题 | 横向滚动预设问题，点击自动发送 |
| 回复延迟 | 模拟思考约 600ms |

**原型快捷问题**

- 推荐散心的地方
- 周末一日游推荐
- 一个人旅行安全吗

#### 2.4.3 智能回复（产品规则）

对话由服务端「小途」智能体生成（Spring AI + 记忆 + 工具），须遵守：

| 规则 | 说明 |
|---|---|
| 连续记忆 | 同一用户近期对话可被记住（例如刚说 emo，下一句仍按治愈推荐） |
| 真实可售 | 推荐的盲盒/价格必须来自当前上架数据，禁止虚构 |
| 不开盒越权 | 可以引导去首页开盒，不能替用户支付或指定抽中某条线路 |
| 快捷问题 | 仍展示原型三问，点击即作为用户消息发出 |

**降级（模型不可用时）** 仍用关键词，保证页面能回：

| 触发关键词 | 回复策略 |
|---|---|
| 散心 / 不好 / emo | 推荐治愈系盲盒（乡村治愈、山野露营） |
| 周末 / 一日游 | 推荐周边微度假盲盒 |
| 一个人 / 安全 | 强调线路安全性与陪伴感 |
| 其他 | 随机默认励志/引导开盒话术 |

### 2.7 我的模块

「我的」是用户账号、个人数据统计、订单入口和服务说明的聚合页。未登录展示登录引导；已登录展示完整资料与统计。

#### 2.7.1 个人概览

| 功能点 | 说明 |
|---|---|
| 头像 | 微信授权头像，或默认用户图标；可更换 |
| 用户昵称 | 登录后展示真实昵称；未设置时默认「旅行探险家」 |
| 手机号 | 脱敏展示（如 138****0000），未绑定提示去绑定 |
| 称号 | 与顶栏一致：旅行新手 / 探索者 / 旅行家 |
| 已解锁线路数 | 有效行程条数（已开盒且未退款） |
| 已解锁徽章 | 已收集徽章数 / 总数 |

#### 2.7.2 个人数据统计（用户可见）

四宫格主指标（原型位置保留，计算规则落地，不再写死）：

| 指标 | 计算规则 |
|---|---|
| 出行次数 | 有效行程条数（已开盒且未全额退款） |
| 累计省钱 | Σ（票面价值 − 购入价），仅计入有效行程 |
| 当前等级 | 称号按出行次数；Lv.N 中 N = max(1, 出行次数) |
| 公益里程 | 每笔支付成功且未退款的订单 +1（对应提取 1 元扶持金） |

展开区（点击统计卡片或「更多数据」进入个人数据页）：

| 指标 | 计算规则 |
|---|---|
| 旅行人格 | 最近一次测试结果；未测显示「未测试」 |
| 去过目的地 | 有效行程目的地去重数 |
| 徽章进度 | 已解锁数 / 12，及进度百分比 |
| 累计消费 | Σ 有效订单实付金额 |
| 最近心情 | 最近一次选中的心情标签 |
| 偏好分类 | 开盒次数最多的盲盒分类 |
| 本月出行 | 当月有效行程数 |
| 日记篇数 | 已生成旅行日记次数 |

### 2.8 支付模块（用户端）

支付发生在开盒确认之后、抽线路之前。一笔成功支付对应一次开盒。

#### 2.8.1 下单

| 功能点 | 说明 |
|---|---|
| 创建订单 | 用户确认开盒后生成待支付订单 |
| 订单内容 | 订单号、用户、盲盒快照（名称/售价/保底/分类）、应付金额 |
| 一单一盒 | 每次开盒独立下单，不支持购物车或多件合并 |
| 重复提交 | 同一用户对同一盲盒若已有待支付单，引导去支付或取消后再下 |

#### 2.8.2 收银台

| 功能点 | 说明 |
|---|---|
| 应付金额 | 等于盲盒售价，单位：元 |
| 支付方式 | **支付宝沙箱跳转收银台**（第一期唯一渠道） |
| 跳转说明 | 点击「去支付宝付款」离开本页，进入支付宝沙箱收银台 |
| 倒计时 | 待支付 15 分钟，超时自动取消 |
| 确认支付 | 服务端下单后返回跳转表单/链接，前端整页跳转；返回后轮询订单状态 |
| 取消 | 用户在支付宝取消或关闭，订单保持待支付，可重新跳转；主动取消则已取消 |

#### 2.8.3 支付结果

| 结果 | 后续 |
|---|---|
| 成功 | 支付宝异步通知验签通过 → 订单「已支付」→ 服务端开盒 → 「已开盒」；用户从支付宝跳回后看到翻牌结果 |
| 失败 / 关闭 | 停留待支付，可再次跳转支付宝 |
| 超时 | 订单「已取消」，不占库存、不抽线路 |
| 抽奖失败 | 调用支付宝沙箱退款，订单「已退款」，提示稍后重试 |

#### 2.8.4 订单列表与详情

| 功能点 | 说明 |
|---|---|
| 列表 | 订单号、盲盒名、金额、状态、下单时间 |
| 筛选 | 全部 / 待支付 / 已支付 / 已开盒 / 已取消 / 已退款 |
| 详情 | 盲盒快照、支付渠道、支付时间、开盒结果线路、关联行程、退款信息 |
| 待支付操作 | 继续支付 / 取消订单 |
| 已开盒操作 | 查看行程 / 符合条件时申请退换 |

**订单状态流转**

```text
待支付 → 已支付 → 已开盒 → 完成
   │         │
   │         └→ 已退款（抽奖失败自动退 / 保底退换审核通过）
   └→ 已取消（用户取消 / 超时）
```

#### 2.8.5 退款与退换

| 场景 | 规则 |
|---|---|
| 待支付取消 | 无资金操作，直接取消 |
| 支付成功但未开出线路 | 系统自动全额退款 |
| 价值保底未达标 | 开盒结果票面价值 < 售价 × 120% 时可申请退换（正常抽奖已保证 ≥ 保底价值，此为兜底） |
| 未出行退换 | 已开盒但用户未使用线路，可申请，需客服审核 |
| 已出行 | 不可退 |
| 退款去向 | 原路返回支付渠道 |
| 退款成功副作用 | 对应行程标记无效；该次不计入出行次数、累计省钱、公益里程；已解锁徽章若无其他行程支撑则收回（可选，需运营确认） |

### 3.11 数据统计

时间筛选：今日 / 昨日 / 近 7 天 / 近 30 天 / 自定义。所有金额以「支付成功且未退款」为准，除非另注。

#### 3.11.1 经营概览

| 指标 | 说明 |
|---|---|
| 开盒量 | 已开盒订单数 |
| 成交额 | 有效订单实付合计 |
| 客单价 | 成交额 / 支付成功用户数 |
| 支付成功率 | 支付成功笔数 / 调起支付笔数 |
| 退款金额 / 退款率 | 已退款合计；退款单数 / 支付成功单数 |

#### 3.11.2 用户数据统计

面向运营的用户规模、结构、行为与价值，与用户端「我的」个人统计对应，但是全站汇总。

**规模与活跃**

| 指标 | 说明 |
|---|---|
| 累计注册 | 登录即注册的用户总数 |
| 新增用户 | 统计期内首次登录人数 |
| DAU / WAU / MAU | 当日 / 7 日 / 30 日内有登录或关键行为（开盒、聊天、测试）的用户 |
| 活跃率 | DAU / 累计注册 |

**转化漏斗**

```text
访问 → 选择心情 → 浏览盲盒 → 点击开盒 → 创单 → 支付成功 → 开盒完成
```

每一层人数、转化率、流失率可按渠道（微信/手机）和盲盒分类下钻。

**留存与复购**

| 指标 | 说明 |
|---|---|
| 次日 / 7 日 / 30 日留存 | 新用户在 D1/D7/D30 仍活跃的比例 |
| 复购开盒率 | 有效开盒 ≥ 2 次的用户 / 有效开盒 ≥ 1 次的用户 |
| 平均开盒次数 | 人均有效开盒 |
| 复购间隔 | 两次开盒的平均间隔天数 |

**用户结构**

| 指标 | 说明 |
|---|---|
| 称号分布 | 旅行新手 / 探索者 / 旅行家 人数与占比 |
| 注册渠道 | 手机号 / 微信 |
| 人格分布 | 四类旅行人格人数（仅统计已测试用户） |
| 测试完成率 | 完成人格测试用户 / 累计注册 |
| 新老成交 | 统计期内首单用户 vs 老用户成交额占比 |

**用户价值**

| 指标 | 说明 |
|---|---|
| ARPU | 成交额 / 活跃用户 |
