# 途个惊喜 — 数据库设计

> 对应 `docs/功能模块设计.md` 实体与状态机  
> 数据库：MySQL 8，字符集 `utf8mb4`，时间字段用 `DATETIME(3)`  
> 金额单位：分（整数），接口层再转元  
> Redis：验证码、支付锁、**小途短期对话 Memory**（可选向量）

---

## 1. ER 关系（业务视角）

```text
用户 1 ── N 订单 1 ── 1 支付流水（成功时）
              │
              ├─ 0..1 退款单
              └─ 0..1 行程  N ── 1 线路  N ── 1 分类/盲盒池
                           │
                           └─ 解锁 → 用户徽章 N ── 1 徽章

用户 1 ── N 聊天消息
用户 1 ── N 人格测试记录
用户 1 ── N 心情选择日志
盲盒 N ── 心情标签（多对多或 JSON）
线路 N ── 1 徽章（开盒解锁哪一枚）
管理员 N ── 1 角色
```

线路不直接挂某个盲盒 ID，而是挂 **分类 `category`**：开盒时从「同分类且启用、票面价值 ≥ 该盲盒保底」的线路池抽取。

## 4. 开盒事务（写库顺序）

同一事务内：

1. 校验订单 `paid`、未超时、属于当前用户。  
2. `SELECT ... FOR UPDATE` 锁定订单行。  
3. 查线路池：`category = 快照分类 AND status=on AND value_cent >= min_value_cent`。  
4. 无可用线路 → 生成自动退款单，调支付宝沙箱退款，订单 `refunded`。  
5. 有线路 → 均匀随机一条 → 插 `trip(valid)` → 若无 `user_badge` 则插入 → 订单 `opened` + `route_id` + `trip_id`。

支付宝跳转支付是异步的：

1. `POST /pay` 调 `alipay.trade.page.pay` 或 `wap.pay`，返回跳转表单，订单仍为 `pending_pay`。  
2. 沙箱 **异步 notify** 验签、核对金额与 `out_trade_no` 后，订单改为 `paid`，再执行上面开盒事务。  
3. 同步 return 只负责把用户带回结果页，**不能**单凭 return 开盒。  
4. 前端轮询 `GET /orders/:orderNo` 直到 `opened` 或 `refunded`。

## 5. 统计口径（SQL 语义）

| 指标 | 规则 |
|---|---|
| 有效行程 | `trip.validity = valid` |
| 出行次数 | 有效行程条数 |
| 累计省钱 | `SUM(value_cent - price_cent)` 有效行程 |
| 累计消费 | `SUM(paid_cent)` 且订单 `opened`（退款后不算） |
| 公益里程 | 上述有效开盒订单数 × 配置元 |
| 称号 | 按出行次数套 `level.rules` |
| DAU | 当日有登录或下单/聊天/测试的去重用户 |

退款审核通过：订单 `refunded`，行程 `invalid`，上述汇总自然下降；徽章行保留。
