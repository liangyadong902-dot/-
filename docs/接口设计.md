## 1. 约定

### 1.1 前缀

| 端 | 前缀 | 鉴权 |
|---|---|---|
| 用户端 | `/api/v1` | 标注「需登录」的接口带用户 JWT |
| 管理端 | `/api/v1/admin` | 管理员 JWT + 角色 |

### 1.2 统一响应

```json
{ "code": 0, "message": "ok", "data": {} }
```

| code | 含义 |
|---|---|
| 0 | 成功 |
| 401 | 未登录 / Token 失效 |
| 403 | 无权限或账号禁用 |
| 400 | 参数错误 |
| 404 | 资源不存在 |
| 409 | 业务冲突（重复待支付单、订单状态不允许） |
| 422 | 业务失败（池中无线路、支付失败） |
| 500 | 服务器错误 |

列表：`data: { list, total, page, pageSize }`。

### 1.3 需登录 / 游客

| 可游客 | 必须登录 |
|---|---|
| 盲盒列表、Banner、图鉴定义、人格题目 | 下单、支付、开盒结果、行程、订单、我的统计、退款 |
| AI 聊天（不落库） | AI 聊天落库、日记、测试结果持久化 |

## 4. 用户端 — 订单与支付（核心）

### 4.1 下单

`POST /orders`

```json
{ "boxId": 1 }
```

规则：

- 未登录 401。  
- 盲盒必须上架。  
- 若该用户对该 `boxId` 已有 `pending_pay`，返回 409，`data.orderNo` 为已有单，前端去支付或取消。  
- 成功：`status=pending_pay`，`expireAt` = 现在 + 配置超时。

`data`：`orderNo、amount、boxName、minValue、expireAt`。

### 4.2 取消待支付

`POST /orders/:orderNo/cancel`  
仅 `pending_pay`。

### 4.3 拉起支付宝（沙箱跳转）

`POST /orders/:orderNo/pay`

```json
{ "channel": "alipay" }
```

- 仅 `pending_pay` 且未超时。  
- 服务端调用沙箱 **电脑网站支付** `alipay.trade.page.pay` 或 **手机网站支付** `alipay.trade.wap.pay`（`product=auto` 时按 UA）。  
- 本接口**不**把订单改为已支付。  
- `data`：

```json
{
  "orderNo": "T...",
  "channel": "alipay",
  "payForm": "<form>...</form>",
  "expireAt": "..."
}
```

前端将 `payForm` 写入页面并自动 submit，整页跳转到支付宝沙箱收银台。

同步回跳（给浏览器，不可作为入账依据）：

- 配置 `return_url` 指向用户端页，如 `/#/pay/result?orderNo=`  
- 页面开始轮询 `GET /orders/:orderNo`

异步通知（入账唯一依据）：

`POST /api/v1/pay/notify/alipay`  
验签（RSA2）、核对 `out_trade_no` 与金额、`trade_status` 为成功 → 订单 `paid` → 开盒。应答支付宝 `success`。重复通知幂等。

开盒完成后订单 `opened`，轮询即可拿到行程：

```json
{
  "orderNo": "T...",
  "status": "opened",
  "trip": { }
}
```

开盒失败（无线路满足保底）：调 `alipay.trade.refund`，`status=refunded`，轮询得到 422 语义或状态 refunded。

`channel=mock` 仅当 `pay.mock_enabled=true` 时可用，便于无沙箱账号的单元测试。

### 4.4 订单列表 / 详情

`GET /orders?status=&page=`  
`GET /orders/:orderNo`

状态筛选：`pending_pay` `paid` `opened` `cancelled` `refunded`。

### 4.5 申请退款

`POST /orders/:orderNo/refund`

```json
{ "reason": "未出行退换", "kind": "unused" }
```

- `opened` 且行程仍 valid 才可申请。  
- `kind=value_guard` 仅当票面 &lt; 售价 × 1.2（兜底）。  
- 生成 `pending_review` 退款单。

## 9. 管理端 — 工作台与统计

`GET /admin/dashboard?range=today|7d|30d`

卡片：今日开盒数、成交额、支付成功率、新增用户、活跃用户；待审退款数。

`GET /admin/stats/users` 用户数据统计：

- 规模：累计注册、新增、DAU/WAU/MAU、活跃率  
- 漏斗：访问（有心情或列表请求的用户）→ 点开盒（创单）→ 支付成功 → 开盒完成  
- 留存：D1/D7/D30（按注册队列）  
- 复购：开盒≥2 占比、人均开盒、间隔  
- 结构：称号、渠道、人格、测试完成率  
- 价值：ARPU、ARPPU、消费分层、省钱合计、公益合计  
- 偏好：心情、分类、目的地 Top、徽章解锁率、AI 渗透、日记率  

Query：`from` `to`。第一期可同步聚合，数据量大再改日表。

`GET /admin/stats/pay` 渠道、失败原因、退款构成。

## 10. 关键时序

```text
用户点开盒
  → POST /orders
  → POST /orders/:no/pay { channel: alipay }
      服务端：调支付宝沙箱 page.pay / wap.pay
      返回 payForm
  → 前端 submit，跳转沙箱收银台
  → 用户用沙箱买家付款
  → 支付宝 POST /api/v1/pay/notify/alipay（验签）
      订单 paid → 抽线路 → trip / badge → opened
  → 同步跳回 /pay/result
  → 前端轮询 GET /orders/:no
  → status=opened 后播摇晃翻牌
```

密钥：沙箱 APPID、商户私钥、支付宝公钥只放环境变量 / `application-local.yml`，不进 Git。逐步准备见 `docs/支付宝沙箱准备.md`。

退款：`alipay.trade.refund`，异步可再接 `alipay.trade.refund.notify`（第一期以同步退款结果 + 本地状态为准）。

## 11. 错误示例

| 场景 | code | message |
|---|---|---|
| 未登录开盒 | 401 | 请先登录 |
| 账号禁用 | 403 | 账号不可用 |
| 已有待支付单 | 409 | 请先完成或取消未支付订单 |
| 支付超时 | 409 | 订单已取消 |
| 线路池不满足保底 | 422 | 开盒失败，已自动退款 |
| 已出行申请退 | 409 | 当前状态不可退 |
