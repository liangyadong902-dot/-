# 管理端与用户端对齐优化规格

## Objective

将 `管理端页面原型.html` 与当前 `页面原型.html` 的用户功能对齐，形成可演示的桌面运营工作台。管理端不复制移动端布局，而是让运营人员可以高效完成商品、线路攻略、社区内容、订单和行程的配置与联查。

目标用户：商品运营、线路运营、内容审核、客服及超级管理员。

本轮假设：

1. 管理端继续作为纯 HTML/CSS/JavaScript 原型运行，不接入新后端。
2. 用户端 `localStorage` 数据仍用于同源演示联动。
3. 保留现有“奶油纸张 + 鼠尾草绿”品牌系统，管理端提高信息密度并减少装饰性占位。
4. 不改动用户端页面，不修改现有 Vue 管理项目和服务端代码。

## Scope

### 1. 工作台

- 首页 KPI 与用户端主流程一致：在售盲盒、启用线路、今日开盒、成交额、待退款、待审核社区内容。
- 待办区可直接跳转退款、社区审核、线路攻略补全。
- 热门盲盒展示关联线路数量、保底覆盖情况和开盒量。

### 2. 盲盒管理

- 保留分类、状态、价格、保底、情绪标签和上下架能力。
- 增加关联线路数量与保底校验结果。
- 编辑抽屉提供用户端商品卡片预览和开盒前攻略说明。
- 线路票面低于盲盒保底时给出明确风险提示。

### 3. 线路与攻略管理

- 六条线路与用户端保持同名、同目的地、同票面价值、同图片和同状态。
- 列表展示攻略完整度、景点数量、日程节点数量与关联盲盒。
- 线路详情包含：基础信息、分时日程、沿途景点、餐食住宿、天气备选和安全提醒。
- 每个景点至少包含名称、停留时间、介绍、核心看点和游览提醒。
- 支持在详情抽屉中新增/删除景点并保存原型状态。

### 4. 社区管理

- 读取用户端发布的社区帖子，并与内置演示帖子合并展示。
- 提供全部、待审核、已发布、精选、已下架筛选。
- 列表展示封面、标题、作者、话题、关联盲盒、互动和发布时间。
- 内容详情支持通过、下架、设为精选，并显示正文、图片和评论摘要。
- 评论审核与帖子状态保持清晰区分。

### 5. 订单与行程联查

- 订单详情显示支付状态、开盒结果、关联线路和行程入口。
- 行程列表显示线路、目的地、票面价值、有效状态和攻略完整度。
- 行程详情复用线路攻略数据，展示时间轴和具体景点，而不是只显示线路名称。
- 已退款行程保持只读并明显弱化。

### 6. 用户管理

- 用户档案保留身份、偏好、资产和成长四个页签。
- 增加订单、行程、徽章和社区发布数量摘要。
- 当前用户端登录账号继续作为联动数据置顶显示。

## Tech Stack

- 原生 JavaScript
- 浏览器 `localStorage`
- Google Fonts：Caveat、Noto Sans SC、Noto Serif SC

## Code Style

- 数据集中放在 `db` 或明确的常量对象中，渲染函数只负责页面组装和事件绑定。
- 页面函数保持 `renderXxx()` 命名，抽屉详情使用 `showXxx()` 或 `editXxx()`。
- 用户生成文本进入模板前统一转义，避免把输入直接拼入 HTML。
- 沿用 8px 基础间距、奶油色背景、纸色工作区和鼠尾草绿状态色。

```js
function routeCompleteness(route) {
  const checks = [route.schedule, route.attractions, route.planB, route.tips];
  const completed = checks.filter((item) => Array.isArray(item) && item.length).length;
  return Math.round((completed / checks.length) * 100);
}
```

## Testing Strategy

- 静态检查：JavaScript 语法和 `git diff --check` 必须通过。
- 数据检查：六条线路均能解析出日程、景点与攻略完整度。
- 交互检查：导航、筛选、线路详情、景点编辑、社区审核、订单到行程联查均可点击完成。
- 联动检查：在用户端发布帖子或开启盲盒后，刷新管理端能看到对应帖子、订单和行程。
- 视觉检查：在 1440x900、1280x800 和 1024x768 下截图检查，不出现横向页面溢出、按钮遮挡或抽屉内容不可达。
- 控制台检查：主流程点击过程中无运行时错误。

## Boundaries

### Always

- 保留用户当前未提交修改。
- 沿用现有数据键 `TUGE_APP_STORE` 与 `TUGE_LEDGER`。
- 所有状态与文案使用中文并与用户端一致。
- 编辑后执行语法、格式和浏览器交互验证。

### Ask First

- 改动 Vue 管理项目、Java 服务端、数据库结构或 OpenAPI。
- 引入第三方框架、图表库或新的远程服务。
- 删除现有管理模块或更改用户端业务规则。

### Never

- 清空用户端 `localStorage` 数据。
- 用静态占位替代已经存在的用户端真实演示数据。
- 将内部详情页堆入一级导航。
- 破坏订单、退款和行程之间已有的演示联动。

## Success Criteria

1. 管理端六条线路与用户端一一对应，并能查看完整的逐景点攻略。
2. 盲盒列表可判断关联线路是否满足保底，编辑时能看到用户端预览。
3. 用户端发布内容能出现在管理端社区列表并完成审核动作。
4. 订单详情可进入对应行程，行程详情可查看具体时间轴和景点。
5. 工作台待办可直达退款、社区和攻略补全模块。
6. 主要页面在三种桌面尺寸下无遮挡、溢出或不可达操作。
7. JavaScript 语法、差异格式和浏览器控制台检查全部通过。
